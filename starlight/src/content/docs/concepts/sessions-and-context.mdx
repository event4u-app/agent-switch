Agent Switch knows every session that ran on each of your accounts. You can see
which ones are running right now, how full each context window is, and whether
continuing costs a full re-read of the conversation. It reads this from your
own session files, on your machine. No API calls are involved.

## Every session, per account

```bash
agent-switch sessions             # recent and running sessions, grouped by account
agent-switch sessions work        # one account
agent-switch sessions --recent 20 # more history
```

Running sessions are marked. For Claude Code, a running session also shows:

- **context %**: how full its context window is, e.g. `67% · 134k/1000k`. This
  matches what Claude Code's own `/context` reports. For an unknown model you
  see the raw token count, never a guessed percentage.
- **prompt cache**: whether the cache is still warm (`cache warm till 10:42`) or
  what the next turn will re-send once it is cold (`cache cold · ~182k re-sent`).

Codex sessions show their context from the session's own log.

The desktop app shows the same in **Sessions**, with a preview of each session's
first turns.

## One account, one session

Several sessions on one account share its limits, and both keep the same login
fresh. It is easy to end up there by accident, for example when two terminals
start `claude` on the same preferred account. The single-session guard notices
this:

| Policy | What a second start on a busy account does |
|---|---|
| `warn` (default for new installs) | Starts, and tells you the account is already in use. |
| `block` | Starts on the best free signed-in account instead, and says so. When every account is busy, it shares the best one. |
| `off` | Starts without comment. |

```bash
agent-switch guard block
```

A `claude` started inside a running session counts as part of it, not as a
second session. A crashed session leaves nothing behind that could lock you
out. To allow one duplicate start on purpose, set
`AGENT_SWITCH_ALLOW_DUPLICATE=1` for that command.

## Context alerts <Badge text="Claude only" variant="note" />

```bash
agent-switch alerts on --threshold 80,95
```

When a running session's context passes a threshold, the background service
records one notice with the project, the percentage and a suggested `/compact`.
Alerts are off by default.

For precise session state, install Agent Switch's hooks into an account's
Claude Code settings:

```bash
agent-switch hooks install work
```

They report when a session starts, stops, compacts or waits at a usage limit,
why a turn stopped (for example a usage limit or a sign-out), and when a
subagent starts and stops. They record ids, event types, error codes, a few
counts and folders, never what you or Claude wrote.

| Event | Records |
| --- | --- |
| `SessionStart`, `SessionEnd` | the session, how it started (new, resumed, after `/clear` or a compaction) |
| `PreCompact`, `PostCompact` | that the context was compacted |
| `Stop`, `StopFailure` | that a turn ended, and the error code if it failed |
| `Notification` | that Claude waits for you, or for a usage limit to reset |
| `SubagentStart`, `SubagentStop` | the subagent's id, type and working folder, under its session |

Each event starts one short `agent-switch` process: about 45 ms and 40 ms of
CPU on an Apple-silicon Mac, 4 CPU seconds per 100 events. With the `as-hook`
relay from the release page in place (`agent-switch hooks relay <file>`), a
running Agent Switch takes the event in about 5 ms instead, and the relay falls
back to `agent-switch` when the app is not running. The hooks are
added next to your own and removed cleanly with `hooks uninstall`. They run in
the background, so a turn never waits for them. Run `hooks install` again after
an update to pick up new events; `hooks status` also brings hooks installed by
2.11 or older, which made each turn wait, to the background form.

Codex accounts get the same hooks in their own `hooks.json`, next to any hooks
you have there:

```bash
agent-switch hooks install work --provider codex
```

They report when a Codex session starts, ends a turn and ends, with its working
folder, never what you or Codex wrote. Codex runs a hook only after you approved
it: the next time you start `codex` for that account, it asks, and you choose
"Trust all and continue" or review them. Agent Switch never approves hooks for
you; `hooks status --provider codex` tells you whether they run yet. A relay
added or removed later changes the hooks, so Codex asks once more.

## Compacting from outside <Badge text="macOS & Linux" variant="caution" />

```bash
agent-switch run work --tmux    # start a session in a managed tmux pane
agent-switch compact work       # later: type /compact into it
```

`compact` only types into a pane that Agent Switch started with `run --tmux`.
It refuses while a turn is running unless you pass `--force`. Anywhere else it
prints the command for you to run. `--clear` sends `/clear` instead, which
discards the conversation, so it also needs `--force`. Nothing is ever
compacted automatically.

<Aside type="tip">
  On a cold cache, `/compact` re-reads the whole history without the cache.
  `compact` says so before it types.
</Aside>

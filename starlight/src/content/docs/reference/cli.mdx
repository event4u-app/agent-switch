Every command the `agent-switch` binary accepts, grouped by task. In the CLI an
account is called a **profile**: wherever you see `<name>` or `<profile>`, it
means the name you gave an account with `add` or `import`.

For the ideas behind the commands, start with
[How it works](/agent-switch/concepts/how-it-works/) and
[Which account a session uses](/agent-switch/concepts/which-account/).

## Global flags

| Flag | What it does |
| --- | --- |
| `--provider claude\|codex\|antigravity` | Which tool the command is about. Default: `claude`. |
| `--json` | Machine-readable output, where the command supports it. |

```bash
agent-switch use work                     # a Claude account
agent-switch use work --provider codex    # a Codex account
```

A flag that takes a value always consumes the next word, so
`agent-switch remove --provider codex old` removes the Codex account `old`.

Running `agent-switch` with no command starts the desktop app (same as
`agent-switch gui`).

## Accounts

| Command | What it does |
| --- | --- |
| `add <name> [--browser B] [--isolated]` | Create an account and sign it in with the tool's own sign-in. `--isolated`: the sign-in opens in this account's own browser profile (Chrome, Brave, Edge, Vivaldi or Chromium started with its own `--user-data-dir`; the same folder `web` uses), so every account keeps its own Google login. Without such a browser, Playwright's Chromium (Google may refuse its SSO). A second Codex sign-in while one runs uses a device code (Codex's sign-in holds port 1455). |
| `import <name>` | Turn the login you already have into an account, without signing in again. See [below](#import-and-shared-logins). |
| `login <name> [--browser B] [--isolated]` | Sign an existing account in again (signed out, or login expired). Gives an imported account its own login. `--isolated` as for `add`. |
| `browsers` | Browsers `--browser` can open; `--json` marks the ones `--isolated` can use (`isolatable`). <Badge text="macOS" variant="caution" /> and Linux. |
| `mark-shared <name> [--off]` | Mark an account as sharing the default install's login (for imports made by older versions). |
| `agent-config-root <name> [own\|global\|status] [--json]` | Claude only. `own`: the account's sessions and the app's agent-config settings use `~/.agent-switch/claude/<name>/agent-config`; `global` (the default): the shared agent-config settings. | `list` / `ls` | All accounts, grouped by tool; the preferred account is marked `*`. |
| `status [name]` | Who each account is signed in as, plus its usage. `--json` covers the preferred account only. |
| `current` | The preferred account per tool. |
| `whoami [name]` | Which account identity an account is signed in as. |
| `auth-status [--json]` | Login state per account: `connected`, `expiring`, `sign-in-needed` or `unknown`. Never prints a token. `--json` prints `{schema, profiles[]}`. |
| `rename <old> <new>` | Rename an account; its tag, colour and folder rules follow. |
| `label <name> [Work\|Personal\|Other\|none]` | Tag an account. |
| `color <name> [orange\|red\|yellow\|green\|teal\|blue\|purple\|pink\|none]` | Pick the account's colour in the app (`colour` works too). |
| `disable <name>` / `enable <name>` | Keep an account but stop using it, or turn it back on. |
| `remove <name> [--force] [--yes]` / `rm` | Delete an account and its login. Asks on a terminal; `--yes` skips the question. |

### `add` and `login`

`add` runs the tool's own sign-in in the new account's folder:
`claude auth login` for Claude, `codex login` for Codex. Antigravity has no
separate sign-in command; `agy` asks you to sign in when it starts.

If the sign-in does not finish, the account is kept and `add` exits with `1`.
Finish it with `agent-switch login <name>`.

`login` on a Claude or Codex account that is already signed in to someone signs
in in a separate folder first. Only a sign-in to the same account (same email,
and for Claude the same organization) replaces the login. A different account
saves nothing, keeps the old login and exits with `4`. Antigravity signs in in
place, so `login` can only report a changed account afterwards (also exit `4`).

`--browser <id>` opens the Claude sign-in in that browser (ids from
`agent-switch browsers`). It is refused on Windows. Codex opens your default
browser itself; the link it prints works in any browser.

### `import` and shared logins

`import` copies your current setup into a new account, so you do not sign in
again. The catch: the new account and your default install now **share one
login**. Whichever side refreshes the login first signs the other out.

So agent-switch marks such an account, and then:

- a balanced start never picks it,
- the background service never refreshes its login,
- `doctor` names it.

`agent-switch login <name>` gives it its own login and clears the mark. For an
import made before the mark existed, set it with `mark-shared <name>`.

### `remove`

`remove` refuses without `--force` when the account:

- is the preferred account,
- has a running Claude session,
- is in the middle of a live switch (`rebind`), or lends its login to another
  account's live switch.

With `--force`, a live switch is undone first. On macOS the account's keychain
entry is deleted too. Folder rules that point at it are removed.

### `disable`

A disabled account keeps its login, history and settings. It is never the
preferred account, `use` refuses it, folder rules and pools skip it, and the
background service stops checking its usage.

| `shellenv [--shell S]` | Print the shell integration. |
| `shellenv install [--shell S]` | Add the shell integration to your shell's startup file. |

### Which account a start uses

A plain `claude` (or `codex`, `agy`) in a terminal with the shell integration
goes through these steps, in this order:

1. **The wrapper.** The `claude` function from `shellenv` runs
   `agent-switch dir --provider claude --guard` in the current folder. If
   `agent-switch` is missing or fails with any exit code other than `86`, the
   real `claude` starts on its own default login: agent-switch never stands
   between you and the tool.
2. **A folder rule** for this folder or the nearest parent folder: that account,
   or the best account in that pool. A **remote binding** counts as a rule on
   the repository's root folder: it matches the `origin` remote (the first
   remote when there is no `origin`), `host/owner/repo` before `host/owner`.
   Walking up from the start folder, the first rule found wins, and a folder
   rule wins over a remote binding on the same folder. So a folder rule inside
   the repo or on its root beats the remote binding, and the remote binding
   beats a rule on a parent folder such as `~/code`. A rule that cannot be
   served (its account is disabled or removed, or its pool has no usable
   account) refuses the start with exit code `86`.
3. **No rule: the start strategy** (`strategy`, per tool) decides among the
   accounts that can take work (enabled, signed in, not sharing the default
   login):

   | Strategy | The start goes to |
   | --- | --- |
   | `balance` (default) | the account that would lose the most at its next reset; the preferred account on a tie or when no account has usage numbers from the last 10 minutes |
   | `fill` | the preferred account until it reaches its limit, then the balanced pick |
   | `default` | always the preferred account; the balanced pick only when it cannot take work |
   | `ask` | the account you choose at a numbered prompt (Enter takes the preferred one). The prompt only appears when stdin and stderr are both a terminal and two or more accounts can take work; a script, a pipe, `exec` and the desktop app are never asked and take the preferred account. An answer that names no account starts nothing (exit `86`). |

4. **Nothing to pick:** when no account can be weighed and no preferred account
   is set, the wrapper prints nothing and `claude` starts on its own default
   login (`~/.claude`).
5. **One account, one running session** (`guard`): the note or the move to a
   free account described [below](#guard).
6. **Start admission:** the picked account's settings are synced, then its
   sign-in is read again. If it changed since the pick (a sign-in or a rebind
   landed in between), the start is refused with exit code `86` and both
   sign-ins are named.
7. **The start:** with `terminal-sync` on, an interactive start runs in Agent
   Switch (see [below](#terminal-starts-run-in-agent-switch)). Otherwise the
   wrapper sets `CLAUDE_CONFIG_DIR` to the account's folder and runs the real
   `claude` with your arguments. The wrapper runs the tool
   itself after `dir --guard` has exited, and that last step is not checked
   again: from there on the pick is advisory.

Every start through the wrapper is recorded in `picks`. `dir --json` prints
`{profile, configDir, why[], blocked?, note?, ask?}` (`ask` lists the accounts
to choose from under `strategy ask`) and starts nothing; `--plain` ignores
folder and remote rules. `exec` runs the same pick, admission and start without a shell (it never asks).
Details: [Which account a session uses](/agent-switch/concepts/which-account/).

`--exclude a,b` leaves those accounts out of this one pick, for a caller that
just saw one of them fail (a limit, an outage) and wants another.


### Terminal starts run in Agent Switch

With `terminal-sync` on (the default) and tmux installed, a `claude` or
`codex` you type in your own terminal runs in Agent Switch's host, and your
terminal shows it. It is one session with two windows: what you type in the
terminal and what you type in the app reach the same program, and both see
everything. The wrapper asks `dir --guard --launch` as before, then hands the
start to `launch`, so account, folder rules, `ask` and the guard work as above.

- **Your shell's environment comes along** (PATH, project variables). It passes
  through a file only you can read, which the session removes before the
  program starts; it never appears in a process list.
- **Ending the program** (`/exit`, Ctrl-D) ends the session and your terminal
  returns to its prompt with the program's exit status.
- **Closing the terminal window** leaves the session running in Agent Switch.
  Join it again with `agent-switch host attach <session>`, or end it in the app.
- **A resume** (`claude --resume <id>`, `--session-id <id>`) keeps its id and
  runs on the account that holds the session, whatever the folder routes to.
  `claude -c` resumes the folder's newest session on the routed account.
- **Typing from both sides at once:** when the app sends something into the
  session, it waits until nobody has typed in an attached terminal for 3
  seconds, at most a minute, and never sends Enter after a key someone typed
  in between.
- **Not hosted, exactly as before:** `-p`/`--print`, `--output-format`,
  `--version`, `--help`, subcommands (`claude mcp`, `codex exec`, …), the
  `--resume` picker, `--fork-session`, a pipe instead of a terminal, Windows,
  no tmux, and a start inside an Agent Switch window. `agent-switch
  terminal-sync off` turns it off; so does Settings › Open in.
### `exec`

The shell integration only works in a shell. A tool that starts `codex` or
`claude` as a subprocess (a script, a review bot, a council of models) never
runs it, so every start lands on the tool's own default login. `exec` does the
shell integration's job without a shell:

```bash
agent-switch exec --provider codex -- exec --json -
```

It picks the account like a terminal start (and records it in `picks`), sets
`CODEX_HOME` / `CLAUDE_CONFIG_DIR` for that account and runs the tool with
everything after `--`. Input, output and the exit code pass straight through.
With no usable account the tool runs on its own default login, with one line on
stderr saying so. A folder rule that cannot be served exits `86`.

### `run`

`run` names one account explicitly. Everything after the account name is passed
to the tool, so `agent-switch run work -- --resume` resumes the last Claude
conversation on `work`. Without an account it starts on the one a plain start
picks for the folder (folder rules, strategy, the `picks` record), and refuses
where a plain start would.

- `--cwd DIR` starts it in that folder.
- `--tmux` starts it in a tmux session agent-switch manages (macOS and Linux).
- `--force` starts it even if that account already has a running session.
- `--model M` starts it on that model (Claude and Codex).
- `--effort E` sets the thinking level: Claude's `--effort` (`low` to `max`),
  Codex's `model_reasoning_effort` (`minimal` to `high`). Antigravity takes
  neither and refuses them.
- `--worktree` starts it in a new git worktree of the folder: branch
  `agent-switch/<tool>-<time>` at the folder's `HEAD`, checked out in
  `<repo>.worktrees/<tool>-<time>` beside the main repository — also when the
  folder is itself a worktree, so worktrees never nest. A second start in the
  same second gets `-2`, `-3`, …. The worktree is made only after the start is
  allowed (a start the single-load guard refuses makes none, and a hosted start
  that fails takes its worktree back). Agent Switch never removes a worktree a
  session used; `sessions cleanup` removes those whose PR is merged, or remove
  one with `git worktree remove` and its branch with `git branch -D`.
- `--new-window` starts it in a new window of the terminal set with
  `open-terminal` instead of this one, after the same routing and guard; the
  account is named on the line that window runs. Warp cannot run a command, so
  Terminal opens instead on macOS. This is what the app's
  **Start in &lt;terminal&gt;** does.

These only count as agent-switch flags before a bare `--`.

### `guard`

| Policy | What happens when the account already has a running session |
| --- | --- |
| `warn` (default on new installs) | A one-line note, then the session starts. |
| `block` | A plain start moves to a free, signed-in account with the most room. If none is free, it shares the best busy one. `run <name>` is refused. |
| `off` | No check. |

The check covers Claude only: Codex and Antigravity leave no sign of a running
session on disk. A session started from inside another one on the same account
is never counted. To start a second session on one account once, use
`run <name> --force` or set `AGENT_SWITCH_ALLOW_DUPLICATE=1`.

| `pool add\|remove <id> <provider/name>` | Change members, e.g. `pool add client-a claude/work`. |

### `shellenv`

The integration defines `claude`, `codex` and `agy` wrappers plus `asw`
(`asw` lists accounts, `asw work` sets the preferred Claude account,
`asw codex work` the preferred Codex account).

| Shell | Load it with | `shellenv install` writes to |
| --- | --- | --- |
| zsh | `eval "$(agent-switch shellenv)"` | `~/.zshrc` |
| bash | `eval "$(agent-switch shellenv)"` | `~/.bash_profile` on macOS, `~/.bashrc` elsewhere |
| fish | `agent-switch shellenv --shell fish \| source` | `~/.config/fish/config.fish` |
| PowerShell | `agent-switch shellenv --shell powershell \| Out-String \| Invoke-Expression` | the `$PROFILE` PowerShell reports |

`cmd.exe` has no integration; use `agent-switch run <name>` there.

## Usage & limits

| Command | What it does |
| --- | --- |
| `status [name]` | Usage per account: 5-hour and weekly meters (Claude, Codex). |
| `limits [--json]` | Every account's limits from cache, with whether it can take work now, why not, and how fresh the numbers are. Reads no network. With `--json` each account also carries `snapshot`, the stored readout as it was read, which the app's tray shows. |
| `switch list\|show\|request\|decide …` | Switch requests near a limit: list or show them, raise one for an account or session, or record your decision (`approve [--to A] [--how after-turn\|now\|handoff]`, `decline`, `snooze`). The first decision counts, in the app, here or in agent-config; the background service carries out an approval. Never moves anything by itself. |
| `pace [on\|off\|status] [--json]` | Suggest moving a session when its account runs out well before its reset while another account of the same provider would let room expire (default on). Only asks — the suggestion is a switch request you answer like one near the limit. |
| `link [on\|off\|status] [--json]` | Let agent-config connect to this Agent Switch (default on). Off, `mcp serve` offers no tools and agent-config removes its wiring. |
| `link executor [app\|service] [--json]` | Who carries out a move you answer in the app's near-limit sheet: the app (default), or the background service. See [Working with agent-config](/agent-switch/guides/agent-config/#who-carries-out-an-answer-given-in-the-app). |
| `mcp serve` | The local MCP server agent-config starts over stdio: limits, this session, and switch requests. No port, nothing listening. |
| `usage history [--profile <name>]` | Usage samples the background service recorded. |
| `protection` | Limit protection per account (default on at 98%). |
| `protection set <provider/name> [--on\|--off] [--threshold N]` | Change one account's limit protection. |
| `protection wait on\|off\|default <claude/name>` <Badge text="Claude only" variant="note" /> | At 100%: let Claude Code wait for the reset (`on`), stop (`off`), or follow Claude Code's own default (`default`, removes the setting). |
| `protection wait on\|off\|default --all [--yes]` <Badge text="Claude only" variant="note" /> | The same for every Claude account. Without `--yes` it only lists each settings file it would write (a shared `settings.json` once, with every account it serves); with `--yes` it checks them again, writes each, and reports any it could not write (exit 1). |
| `autoswitch on\|off\|status [--threshold N] [--tag T]` | Limit suggestions: a notification that names the account with the most room. Never switches. Default off. |
| `reset <name> --provider codex [--yes]` | Use one banked Codex limit reset. Asks first on a terminal, then waits until the usage readout shows the cleared limit. |
| `auto-reset [on\|off\|status]` | At 100 % the background service uses one banked Codex reset by itself, at most once per reset cycle (default off). |
| `keep-signed-in [on\|off\|status]` | Let the background service keep unused logins from running out (default on). Each provider's own tool does the refresh; Antigravity on macOS only. |

<Aside>
`autoswitch` only notifies and suggests. A running session changes account only
when you confirm a [live switch](#rebind). See
[Limits & protection](/agent-switch/concepts/limits-and-protection/).
</Aside>

### `protection`

Limit protection does two things:

- a balanced or pool start skips an account that has reached its threshold on
  any limit;
- the background service shows a warning when a checked account reaches it.

It pauses nothing. `protection --json` also shows, per Claude account, what
Claude Code itself does at 100% (`hostWaits`: `on`, `off`, `default` or
`unknown`). `protection wait` writes Claude Code's `autoContinueAtUsageLimit`
setting; `protection wait default` removes it. If several accounts share one `settings.json`, all of them change, and
the command lists them.

### `autoswitch`

Works for Claude and Codex (they have usage numbers). `--threshold` is 1–100
(default 95). `--tag all|work|personal|other` limits which accounts may be
suggested. The background service must be running.

### `sessions rm`

`--yes` is required. A running session is never removed. When several accounts
share one history folder, it also asks for `--ack <session-id>`, because the
session disappears for all of them.

### `takeover`

Moves by default. Options:

- `--from <profile>` names the source account;
- `--keep-source` copies instead (the copy gets a new session id);
- `--in-place` continues inside the tmux pane of a `run --tmux` session;
- `--print-only` prints the resume command instead of running it;
- `--force` skips the running-session check.

### `rebind`

Switches the account of a **running** Claude session on macOS. The session uses
the new account from its next message.

| Form | What it does |
| --- | --- |
| `rebind` | Pick the account in a list (the one with the most room is pre-selected). |
| `rebind <account> [--profile <p>]` | Switch now. |
| `rebind <account> --when-idle [--session <id>]` | Switch once the session's current turn ends. Expires after 30 minutes. |
| `rebind --cancel [--profile <p>]` | Drop a waiting `--when-idle` switch. |
| `rebind --restore [--profile <p>]` | Give the session its own account back. |
| `rebind --reset` | Re-enable `rebind` after it turned itself off following 3 failed attempts. |
| `continue <provider/account/session> [--text "…"]` | Type one message (default “Continue where you left off.”) into a session Agent Switch hosts. Only into an empty input: when you left a draft there, or the input line cannot be seen, nothing is sent and it says why. |

`rebind` moves the target account's login into the running session, so the
target's own account is signed out while it is lent. It therefore refuses a
target that has a running session of its own: that session would lose its login.
It switches the account, not one session: when two or more sessions run on the
account, it names each of them (`Rebinding "work" moves every live session on it
to side's account — 2 follow: …`) before it switches, and the app says the same
in its confirmation.

`rebind` moves the target account's login into the running session, so the
target's own account is signed out while it is lent. It therefore refuses a
target that has a running session of its own: that session would lose its login.

See [Move a session](/agent-switch/guides/move-a-session/).

### `doctor` checks

- `agent-switch` is on your PATH;
- the shell integration is loaded from a startup file;
- the desktop app starts at login;
- no API key in your environment overrides the account logins;
- Antigravity support on this OS;
- every account has a stored login, and no two accounts are signed in as the
  same identity;
- accounts that share the default install's login;
- shared settings links are intact;
- where `statusline on` was run: whether the status line is still Agent
  Switch's, was replaced by another one, or is gone;
- the guard policy, and whether an account runs twice right now.

`--json` prints `{schema, readiness, platform, checks[]}`. It names an API-key
variable, never its value.

`schema` in the JSON of `doctor`, `auth-status` and `activity` is the shape's
version, today `1`. A new field keeps the number; it goes up when a field is
removed or changes meaning.
